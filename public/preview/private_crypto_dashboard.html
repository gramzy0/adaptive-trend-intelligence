E. Limitations

  • Private research tool. Unlisted preview — access by direct link only; not indexed, not advertised, and not for public promotion.
  • No financial advice. Nothing here is a recommendation to take any action.
  • No buy/sell/hold language. This dashboard does not label any asset as a buy, sell, or hold.
  • No automated execution. Nothing on this page places, triggers, or authorizes a trade.
  • Human review required. Every state, flip, score, and reason is a data point for a person to evaluate, not a conclusion.
  • Crypto reflects a single local snapshot only (see generated time above); no cross-source freshness, ranking-adapter, or outcome-history join is applied.
  • State/flip fields reflect the CTO Larsson trend classifier only; "Unknown" means the classifier had insufficient candle history for that asset.
  • Stock data (section B), when present, comes from a fixed weekly snapshot file and may be several weeks stale — see the note under that section for its exact file modification time.
  • Commodity data (section C) does not exist yet in this repository's outputs; the checked candidate filenames are listed under that section, and no commodity data is invented.
  • Chart buttons link to TradingView in a new tab; no chart is embedded, no indicator is added, and no TradingView login is required or automated. A missing source link is shown as "No chart link" rather than a guessed URL.
  • Market context panels (crypto/stocks/commodities) read local, optional JSON files only; none are fetched from an API or scraped, and none require manual input to render the dashboard — a missing file simply shows "Automated market context not connected yet."
  • Reasoning column (today's flips only): each headline's relevance (Direct match / Market context / Unrelated) and freshness (Today / Recent / Old / Unknown) are computed by lightweight text heuristics, not verified fact-checking. The Strong/Medium/Weak quality badge summarizes those heuristics for the coin as a whole; only the best 3 headlines are shown by default (rest under "Show N more"), and a Weak label is always shown, never hidden silently.
  • Crypto market cap rank: missing, blank, zero, or non-numeric values are shown as "—" and always sort to the end of the "Mkt cap rank" column regardless of sort direction; no fake rank number is ever displayed.
  • Current color age: counts consecutive daily candles (the scanner's "1d" interval) holding the asset's current Blue/Gray/Gold state, shown as days elapsed since it last changed ("New today" = changed on the most recent candle). "Unknown" means the scanner had too few candles to determine a color at all — never guessed. Sorts numerically; "Unknown" always sorts to the end, same rule as market cap rank.
  • Priority score (today's flips only): a 0–100 value that orders flipped assets for review convenience, computed from existing local scanner and reasoning outputs only — flip transition (direction-agnostic; a full Blue↔Gold reversal scores higher than a partial move through Gray), market-cap rank (missing/blank/zero scores 0), current color age, Strong/Medium/Weak reasoning quality, freshest coin-specific headline, and score tier — with component weights that sum to 100. It ranks nothing as better or worse as an asset, implies no bullish/bearish direction, and is not a recommendation, rating, signal, or instruction to act. "High / Medium / Low priority" refers only to suggested review order (thresholds: High ≥ 70, Medium ≥ 45). The flips table is sorted by it by default; every other column still sorts on click.
  • Peg/stable pairs are excluded from flip review. Stablecoin-vs-stablecoin and same-currency USD-pegged pairs (for example USDS/USDT, USDC/USDT, DAI/USDT) are left out of Today's flips, the priority ranking, the quick-chart flip buttons, the flip-transition summary, and the confirmed-flip count shown for review. A CTO color change on a same-currency pegged pair almost always reflects peg deviation, bid/ask spread, or thin-liquidity microstructure — not a directional trend in the underlying asset — so counting it as a meaningful flip would be misleading. Membership is an explicit reviewed asset-code list, not a substring match on “USD”, so genuine fiat pairs such as GBP/USDT are unaffected. These pairs stay visible in the full crypto table above (flagged as an excluded peg pair) and are never removed from the raw scanner output.
  • Watchlist and saved filters are local-browser-only. The ☆/★ Watch toggle (both tables) and the filter bar's saved state (search, flips-only, hide-D-Ignore, watchlist-only, state, tier, priority, reasoning quality) persist to this browser's localStorage only — no login, no account, no server-side storage, nothing synced across devices. A symbol is watched by ticker only: if a ticker is ever delisted and later reused for a different asset, a stale local entry could point at the wrong one. The watchlist stores a symbol and an optional free-text note only — never a quantity, price, cost basis, PnL, or portfolio value. If browser storage is unavailable (e.g. private browsing), the page and its filters still work normally within that view; nothing simply persists across a reload.
  • Full crypto table is asset-level. One row per base asset, grouping that asset's USDT pair and BTC pair; USDT current state / USDT color age and BTC current state / BTC color age are separate columns, and a pair the scanner does not carry shows an em dash. Missing color age sorts last, never as zero. The Flip column combines both pairs into a neutral marker (USDT flip / BTC flip / Both / No). Score, tier, market-cap rank and reason come from the higher-scoring pair (USDT on a tie). Previous state and flip direction are not shown here — they remain in Today's flips. Search matches the base asset, the USDT symbol, or the BTC symbol; the state filter matches if either pair's current state matches. The Watch toggle and the "Watchlist only" filter act on the USDT pair symbol (or BTC when there is no USDT pair); a row also shows as watched if the other pair's symbol is already in the local watchlist, but toggling only adds/removes the USDT symbol. The pair-level reports/private_crypto_dashboard.csv is unchanged for existing consumers; an additive asset-level reports/private_crypto_dashboard_asset_pairs.csv (also copied to public/preview/) carries the grouped view.
  • Per-symbol candle freshness gate. The scanner stamps every pair with the recency of its latest closed daily candle (data_as_of / candle_age_days / data_freshness_status, appended to data/output/cto_scanner_debug.csv and both dashboard CSVs). A pair with ≥ 120 candles can still have a latest candle that is months or years old (a delisted symbol whose klines history froze, a data outage); that series would otherwise produce a confident current state and colour age. A pair that is not fresh (latest closed candle older than three days) or whose recency is unknown stays in the full crypto table — muted, labelled, with the staleness noted in its reason cell — but is kept out of Today's flips, the priority ranking, the quick-chart buttons, the transition summary, and the confirmed-flip count. The USDT and BTC legs of an asset are judged separately. This is a data-quality guard, not a market call; the threshold is a first-cut V0 value. Until the next scanner run adds the freshness columns the page shows “Pending” and gates nothing. The flip-history ledger likewise drops currently-stale symbols from its meaningful rollups.
  • Historical flip memory (Today's flips columns: Last flip, Days since last flip, Prior flips, Pattern, Outcome). Read from the local reports/flip_history/ ledger, which is rebuilt each day from the dated per-flip reasoning files. It collapses repeated daily confirmations of the same unchanged flip into one distinct event with several observed dates (so a pair that stays flagged for many days counts once, labelled “Unchanged / stale”, not many times). Pattern is one of six neutral triage labels — First observed, Repeat, Frequent, Alternating, Unchanged / stale, Insufficient history — and is not a signal, rating, or direction. Coverage currently spans only a few days, so windows of 14/30 days are partly covered and most symbols read “Insufficient history”; a day the daily build did not run is a gap in which a flip may be missed. A flip is dated by the scan day it was first confirmed (the underlying colour change is about a day earlier). These columns do not feed the priority score. The Outcome column is a placeholder — post-flip outcome tracking is not implemented, and when it is it will describe only the observed CTO state after a flip, never a return, profit/loss, win rate, price target, or recommendation. Peg/stable pairs are excluded from the ledger and these columns, exactly as they are from the rest of flip review. If the ledger file is missing or unreadable the dashboard still builds and every history cell reads “Insufficient history”.
